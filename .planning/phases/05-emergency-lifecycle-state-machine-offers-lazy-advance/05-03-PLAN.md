<threat_model>
ASVS L1 & Concurrency Threat Modeling for Plan 05-03:
- T-05-02 (Double-Accept Race Condition): Two volunteers accept an offer simultaneously, resulting in dual conflicting on-scene claims. Mitigation: Database transaction acquires row lock on `Emergency`; service verifies no other offer has `status IN ('ACCEPTED', 'ARRIVED')`; first committer succeeds; second receives HTTP 409 `OFFER_ALREADY_CLAIMED`.
- T-05-03 (Location Leakage to Unverified or Declining Responder): A volunteer who declined or whose offer expired retains citizen GPS coordinates. Mitigation: `services/privacy.py` returns null coordinates (`lat: null, lng: null, location_revoked: true`) for non-active offers; automated privacy test suite asserts null values.
- T-05-05 (Unauthorized Incident Cancellation): A malicious bystander sends `POST /emergencies/{id}/cancel`. Mitigation: Centralized authorization in `services/authz.py` restricts cancellation strictly to the reporter, patient, or verified authority.
</threat_model>

       - `OfferActionRequest`: `action: OfferAction`, `decline_reason: Optional[str] = None`, `actions_reported: List[str] = []`, `notes: Optional[str] = None`. Config: `extra="forbid"`.
       - `DispatchOfferResponse`: `id: uuid.UUID`, `emergency_id: uuid.UUID`, `track: str`, `target_kind: str`, `rank: int`, `status: str`, `offered_at: datetime`, `expires_at: datetime`, `eta_s: Optional[int]`, `distance_m: Optional[float]`, `scene_safety_warning: Optional[str]`.

    2. Create `backend/app/services/privacy.py`:
       - `calculate_coarse_coordinates(lat: float, lng: float, incident_id: uuid.UUID) -> Tuple[float, float]`:
         - Derives a deterministic pseudo-random bearing and distance (~200m to ~300m, mean 250m) from `hashlib.sha256(str(incident_id).encode())`.
         - Adds degree delta to `lat` and `lng`, rounds to 5 decimal places.
         - Returns `(coarse_lat, coarse_lng)`. Guarantees identical result across repeated calls for the same `incident_id`.
       - `filter_emergency_location_for_user(emergency: Emergency, user: User, active_offer: Optional[DispatchOffer] = None) -> Tuple[Optional[float], Optional[float], str]`:
         - If `user.role == UserRole.AUTHORITY` or `user.id in (emergency.reported_by_user_id, emergency.patient_user_id)`:
           returns `(emergency.lat, emergency.lng, "exact")`.
         - If `active_offer` is provided and `active_offer.status in ("ACCEPTED", "ARRIVED")`:
           returns `(emergency.lat, emergency.lng, "exact")`.
         - If `active_offer` is provided and `active_offer.status == "OFFERED"`:
           `coarse_lat, coarse_lng = calculate_coarse_coordinates(emergency.lat, emergency.lng, emergency.id)`
           returns `(coarse_lat, coarse_lng, "coarse")`.
         - Otherwise (unassigned, expired, declined, cancelled, completed):
           returns `(None, None, "revoked")`.
    3. Create `backend/tests/test_location_privacy_tiers.py`:
       - Test 1: Unaccepted offer returns coarse coordinates shifted by ~200-300m from exact location.
       - Test 2: Coarse coordinates for the same incident are 100% deterministic and do not jump across multiple invocations.
       - Test 3: Accepted offer returns exact coordinates.
       - Test 4: Declined, expired, or completed offer returns null coordinates (`location_revoked: True`).

<task type="auto">
  <name>Task 2: Transactional offer action handler and emergency cancellation/resolution</name>
  <files>backend/app/services/offer.py, backend/app/api/v1/emergencies.py</files>
  <read_first>docs/LIFELINK_MASTER_SPEC.md §5, §7.3, backend/app/models/emergency.py, backend/app/services/advance.py, backend/app/services/privacy.py</read_first>
  <action>
    1. Create `backend/app/services/offer.py`:
       - `execute_offer_action(db: Session, offer_id: uuid.UUID, action_req: OfferActionRequest, user: User, clock: Clock) -> DispatchOffer`:
         - Acquires row lock on `DispatchOffer` and parent `Emergency` using `SELECT ... FOR UPDATE`.
         - Validates authorization: user is the assigned `responder` / `ambulance_operator` or an authority.
         - On `OfferAction.ACCEPT`:
           - Verifies `offer.status == "OFFERED"` and `clock.now() < offer.expires_at`.
           - Single-active-responder check: ensures no other offer on this incident and track is already `ACCEPTED` or `ARRIVED`. If yes, raises `HTTPException(409, "OFFER_ALREADY_CLAIMED")`.
           - Updates `offer.status = "ACCEPTED"`, `offer.accepted_at = clock.now()`.
           - Updates `emergency.community_track = TrackStatus.ASSIGNED`.
           - If `emergency.status in ("CREATED", "TRIAGED", "DISPATCHING")`: updates `emergency.status = EmergencyStatus.IN_PROGRESS`.
           - Appends event `OFFER_ACCEPTED`, `seq=emergency.next_event_seq`.
         - On `OfferAction.DECLINE`:
           - Verifies `offer.status == "OFFERED"`.
           - Updates `offer.status = "DECLINED"`, `offer.decline_reason = action_req.decline_reason`.
           - Appends event `OFFER_DECLINED`.
           - Executes immediate synchronous cascade: queries `find_and_rank_candidates` (excluding previously offered candidate IDs) and creates offer for candidate #2 in `OFFERED` status.
         - On `OfferAction.ARRIVE`:
           - Verifies `offer.status == "ACCEPTED"`.
           - Updates `offer.status = "ARRIVED"`, `offer.arrived_at = clock.now()`.
           - Updates `emergency.community_track = TrackStatus.ON_SCENE`.
           - Appends event `RESPONDER_ARRIVED`.
         - On `OfferAction.SCENE_UNSAFE`:
           - Verifies `offer.status in ("ACCEPTED", "ARRIVED")`.
           - Updates `offer.status = "CANCELLED"`.
           - Sets `emergency.dispatch_plan["scene_safety_warning"] = action_req.notes or "Volunteer reported unsafe scene conditions"`.
           - Appends critical event `RESPONDER_SCENE_UNSAFE` with hazard notes.
           - Cascades to candidate #2 with safety warning in offer snapshot.
         - On `OfferAction.COMPLETE`:
           - Verifies `offer.status == "ARRIVED"`.
           - Updates `offer.status = "COMPLETED"`, `offer.completed_at = clock.now()`, `offer.actions_reported = action_req.actions_reported`.
           - Updates `emergency.community_track = TrackStatus.DONE`.
           - Appends event `RESPONDER_COMPLETED`.
         - Updates `emergency.updated_at = clock.now()`.
         - Commits and returns updated `offer`.
    2. In `backend/app/api/v1/emergencies.py`:
       - Implement `POST /{id}/cancel`:
         - Requires user is reporter, patient, or authority.
         - Cancels active offers, updates track states to `CANCELLED`, updates `emergency.status = EmergencyStatus.CANCELLED`, `emergency.closed_at = clock.now()`.
         - Appends event `EMERGENCY_CANCELLED`.
       - Implement `POST /{id}/resolve`:
         - Requires authority or assigned ambulance operator.
         - Completes active offers, updates `emergency.status = EmergencyStatus.COMPLETED`, `emergency.closed_at = clock.now()`.
         - Appends event `EMERGENCY_COMPLETED`.
  </action>
