<threat_model>
ASVS L1 & Concurrency Threat Modeling for Plan 05-02:
- T-05-04 (Zombie Offer Starvation): An unattended volunteer phone leaves an incident stuck in `OFFERED` status while the patient bleeds. Mitigation: `advance()` checks `expires_at` against `clock.now()` on every poll request, transitions offer to `EXPIRED`, and instantly cascades to candidate #2 in the same database transaction.
- T-05-08 (Lock Contention & Deadlock): Multiple clients polling every 2 seconds cause database connection lockups or deadlocks. Mitigation: Strict lock hierarchy: `emergencies` row is always locked first using `SELECT ... FOR UPDATE`, followed by child offers; short atomic transaction duration (<10ms).
- T-05-09 (Event Sequence Gap / Out-of-Order Timeline): Concurrent pollers insert events with duplicate or conflicting sequence numbers. Mitigation: Row lock on parent `Emergency` serializes event creation, guaranteeing monotonically increasing `seq` via `emergency.next_event_seq`.
</threat_model>

  <action>
    Create `backend/app/services/advance.py`:
    1. Implement `advance_emergency(db: Session, emergency_id: uuid.UUID, clock: Clock) -> Emergency`:
       - Query emergency with row lock:
         ```python
         emergency = (
             db.query(Emergency)
             .filter(Emergency.id == emergency_id)
             .with_for_update()
             .one_or_none()
         )
         ```
       - If `emergency is None`: raise `HTTPException(404, "Emergency not found")`.
       - If `emergency.status in (EmergencyStatus.COMPLETED, EmergencyStatus.CANCELLED, EmergencyStatus.NO_COVERAGE_CLOSED)`:
         return emergency (terminal state, no advancement needed).
       - Evaluate Community Track:
         - Find active community offer where `track == "community"` and `status in ("OFFERED", "ACCEPTED", "ARRIVED")`.
         - If offer status is `"OFFERED"`:
           - Check if `clock.now() >= offer.expires_at`:
             - Mark offer `status = "EXPIRED"`, `responded_at = clock.now()`.
             - Append event: `type="OFFER_EXPIRED"`, `seq=emergency.next_event_seq`, payload with candidate info and timeout duration. Increment `emergency.next_event_seq`.
             - Execute synchronous cascade:
               - Query `find_and_rank_candidates(db, emergency.id, clock)`.
               - Filter for eligible community candidates whose ID is NOT in previously offered / declined / expired list.
               - If next candidate exists (e.g. Ravi Gaikwad):
                 - Create new `DispatchOffer`:
                   `emergency_id=emergency.id`, `track="community"`, `target_kind="responder"`, `responder_id=next_candidate.candidate_id`, `rank=offer.rank + 1`, `status="OFFERED"`, `offered_at=clock.now()`, `expires_at=clock.now() + timedelta(seconds=settings.OFFER_TTL_S)`, `score_snapshot=next_candidate.score_breakdown`.
                 - Append event: `type="OFFER_CREATED"`, `seq=emergency.next_event_seq`, payload with candidate category, ETA, and masked details. Increment `emergency.next_event_seq`.
               - If no candidate exists:
                 - Set `emergency.community_track = TrackStatus.UNAVAILABLE`.
                 - Append event: `type="TRACK_EXHAUSTED"`, track="community".
         - If community track is `TrackStatus.SEARCHING` and has no active offer:
           - Query candidates and dispatch candidate #1.
       - Evaluate Professional Ambulance Track:
         - Evaluate active ambulance offers similarly (check timeout against `expires_at`, cascade to next unit if expired).
       - Check No Coverage Terminal Condition:
         - If both tracks are `TrackStatus.UNAVAILABLE` and no responders/units are assigned, transition `emergency.status = EmergencyStatus.NO_COVERAGE_CLOSED`.
       - Update `emergency.updated_at = clock.now()`.
       - Flush and commit transaction.
       - Return updated `emergency`.
  </action>
  <verify>
    <command>python -c "from app.services.advance import advance_emergency; print('Advance service loaded successfully')"</command>
  </verify>
