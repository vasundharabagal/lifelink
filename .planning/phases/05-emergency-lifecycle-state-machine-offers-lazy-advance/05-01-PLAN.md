<threat_model>
ASVS L1 & Concurrency Threat Modeling for Plan 05-01:
- T-05-01 (Duplicate SOS Storm / Resource Exhaustion): Double-taps or rapid retries trigger multiple simultaneous ambulance/volunteer dispatches for the same person. Mitigation: Database-enforced unique index on `(reported_by_user_id, idempotency_key)` + 150m/10min spatial deduplication engine returning HTTP 409.
- T-05-06 (Schema Poisoning / Invalid Coordinate Injection): Malformed or out-of-range coordinates submitted by client. Mitigation: Strict Pydantic v2 schemas (`extra="forbid"`) with latitude (-90 to 90) and longitude (-180 to 180) validation.
- T-05-07 (Unauthenticated Incident Creation): Anonymous requests spoofing emergency records. Mitigation: Session authentication (`require_user` / `require_role(CITIZEN)`), associating incident directly to verified caller.
</threat_model>

<task type="auto">
  <name>Task 2: Transactional emergency creation service with idempotency, spatial deduplication, triage, and offer dispatch</name>
  <files>backend/app/services/emergency.py</files>
  <read_first>docs/LIFELINK_MASTER_SPEC.md §5, §7.1, backend/app/models/emergency.py, backend/app/triage/rules.py, backend/app/orchestration/service.py, backend/app/core/clock.py</read_first>
  <action>
    Create `backend/app/services/emergency.py`:
    1. Define custom exceptions: `DuplicateEmergencyError(Exception)` holding `DuplicateEmergencyErrorResponse` metadata.
    2. Implement `create_emergency(db: Session, payload: EmergencyCreateRequest, reporter_user: User, clock: Clock, idempotency_key: str) -> Emergency`:
       - Check idempotency key: query `Emergency` where `reported_by_user_id == reporter_user.id` and `idempotency_key == idempotency_key`. If found, return existing `Emergency` immediately (idempotent replay).
       - Check near-simultaneous spatial deduplication if `payload.force_create is False`:
         - Bounding box prefilter for radius $r = 150\,\text{m}$ around `payload.lat`, `payload.lng`.
         - Time filter: `created_at >= clock.now() - timedelta(minutes=10)`.
         - Scope filter: match `demo_session_id`.
         - Status filter: `status NOT IN ('COMPLETED', 'CANCELLED', 'NO_COVERAGE_CLOSED')`.
         - Compute exact Haversine distance; if any active incident has distance $\le 150\,\text{m}$, raise `DuplicateEmergencyError` with `existing_emergency_id`, distance, priority, and `created_at`.
       - Run triage classification:
         - Call `classify_emergency` from `app.triage.rules` with `payload.triage_input`.
         - Derive `priority`, `protocol_id`, `requires_ambulance`, `required_skills`, and pre-reviewed first-aid protocol guidance.
       - Create `Emergency` record:
         - Status: `EmergencyStatus.CREATED` (or `TRIAGED` / `DISPATCHING`).
         - Community track: `TrackStatus.SEARCHING` if community response indicated, else `TrackStatus.NOT_STARTED`.
         - Professional track: `TrackStatus.SEARCHING` if `requires_ambulance`, else `TrackStatus.NOT_STARTED`.
         - Next event sequence: `next_event_seq = 1`.
         - Append initial events to `emergency_events`:
           - Event 1: `type="EMERGENCY_CREATED"`, actor: reporter, visible_to: all.
           - Event 2: `type="TRIAGE_COMPLETED"`, actor: system, visible_to: all.
         - Flush to generate `emergency.id`.
       - Compile candidate dispatch plan:
         - Invoke `find_and_rank_candidates(db, emergency.id, clock, max_search_radius_m=5000)`.
         - Store serialized `OrchestrationResult` into `emergency.dispatch_plan`.
         - Update status to `EmergencyStatus.DISPATCHING`.
       - Create initial offers:
         - If community track has ranked candidates:
           - Candidate #1 gets `DispatchOffer` created: `target_kind="responder"`, `responder_id=candidate.candidate_id`, `rank=1`, `status="OFFERED"`, `offered_at=clock.now()`, `expires_at=clock.now() + timedelta(seconds=OFFER_TTL_S)`, `score_snapshot=candidate.score_breakdown`.
           - Set `emergency.community_track = TrackStatus.OFFERED`.
           - Append Event 3: `type="OFFER_CREATED"`, payload containing candidate category, ETA, and masked details.
         - If community track has 0 candidates:
           - Set `emergency.community_track = TrackStatus.UNAVAILABLE`.
           - Append Event: `type="TRACK_EXHAUSTED"`, track="community".
         - If professional track has ranked ambulances:
           - Unit #1 gets `DispatchOffer` created: `target_kind="ambulance"`, `ambulance_id=unit.unit_id`, `rank=1`, `status="OFFERED"`, `offered_at=clock.now()`, `expires_at=clock.now() + timedelta(seconds=OFFER_TTL_S)`.
           - Set `emergency.professional_track = TrackStatus.OFFERED`.
           - Append Event: `type="OFFER_CREATED"`, track="professional".
       - Commit transaction and refresh `Emergency` with relationships.
       - Return `Emergency`.
  </action>
