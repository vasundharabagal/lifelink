<threat_model>
ASVS L1 Threat Modeling for Plan 02-02:
- T-02-05 (Insecure Direct Object Reference / IDOR): Malicious user guesses an emergency UUID and reads another citizen's location or medical data. Mitigation: `services/authz.py` verifies ownership/participation and raises `404 NOT_FOUND` for non-participants to prevent resource enumeration.
- T-02-06 (Cross-Tenant Data Leakage): Judge in Demo Session A accesses data from Demo Session B. Mitigation: Strict tenant scoping check `request.user.demo_session_id == resource.demo_session_id` on all object-level accesses.
</threat_model>

       - Normalizes roles to string values.
       - If `current_user.role not in normalized_roles`:

       - `require_citizen = require_role(UserRole.CITIZEN)`
       - `require_responder = require_role(UserRole.RESPONDER)`

<task type="auto">
  <name>Task 2: Implement centralized object authorization in services/authz.py</name>
  <files>backend/app/services/authz.py</files>
  <read_first>backend/app/models/emergency.py, backend/app/models/user.py, docs/LIFELINK_MASTER_SPEC.md §10.2</read_first>
  <action>
    Create `backend/app/services/authz.py`:
    1. Define `check_tenant_scope(user: User, resource_demo_session_id: Optional[UUID]) -> bool`:
       - Returns `True` if `user.demo_session_id == resource_demo_session_id`, else `False`.
    2. Define `assert_can_view_emergency(user: User, emergency: Emergency, db: Session) -> None`:
       - If not `check_tenant_scope(user, emergency.demo_session_id)`:
         - Raise `HTTPException(404, detail={"error": {"code": "NOT_FOUND", "message": "Emergency not found"}})`
       - If `user.role == UserRole.AUTHORITY.value`:
         - Allowed.
       - If `user.id in (emergency.patient_user_id, emergency.reported_by_user_id)`:
         - Allowed.
       - If `user.role == UserRole.RESPONDER.value`:
         - Check if user has an active offer for this emergency (`emergency_id == emergency.id and responder_id == user.id`). If found: allowed.
       - If `user.role == UserRole.AMBULANCE_OPERATOR.value`:
         - Check if user's ambulance unit is assigned or offered for this emergency. If found: allowed.
       - Otherwise, raise `HTTPException(404, detail={"error": {"code": "NOT_FOUND", "message": "Emergency not found"}})` (anti-enumeration defense).
    3. Define `assert_can_act_on_offer(user: User, offer: DispatchOffer, db: Session) -> None`:
       - If offer is community responder offer:
         - If `offer.responder_id != user.id`:
           - Raise `HTTPException(403, detail={"error": {"code": "FORBIDDEN", "message": "Offer not assigned to this responder"}})`
       - If offer is ambulance offer:
         - Check if `offer.ambulance` has `operator_user_id == user.id`. If not: raise 403 `FORBIDDEN`.
    4. Define `assert_can_view_medical(user: User, emergency: Emergency, medical_profile: Optional[MedicalProfile], db: Session) -> bool`:
       - If `user.id == emergency.patient_user_id`:
         - Return `True` (patient always sees own medical profile).
       - If not `emergency.consent_share_medical`:
         - Return `False` (medical sharing disabled by patient).
       - If user is assigned responder or ambulance unit operator on an accepted offer:
         - Return `True`.
       - Return `False`.
  </action>
  <acceptance_criteria>
    - Non-participant accessing emergency receives 404 NOT_FOUND (IDOR masking).
    - Cross-tenant access receives 404 NOT_FOUND.
    - Assigned responder or authority is allowed.
    - Responder acting on another's offer receives 403 FORBIDDEN.
    - Medical data withheld when consent is disabled.
  </acceptance_criteria>
</task>
