<threat_model>
ASVS L1 Threat Modeling for Plan 02-01:
- T-02-01 (Brute-Force Password Guessing): Attacker attempts dictionary attacks against citizen/responder accounts. Mitigation: Argon2id memory-hard password hashing and generic login error messages ("Invalid email or password").
- T-02-02 (Credential Stuffing & Weak Passwords): Attacker uses leaked common passwords. Mitigation: Minimum 10 characters length enforcement and common-password denylist check.
- T-02-03 (Token Theft via XSS): Attacker executes JavaScript to steal session tokens. Mitigation: Primary JWT stored in `HttpOnly; SameSite=Strict` (or `Lax` in dev) cookie inaccessible to JavaScript.
- T-02-04 (CSRF State Mutation): Malicious third-party origin attempts authenticated calls. Mitigation: `SameSite` cookie protection and mandatory `Content-Type: application/json` on mutating requests.
</threat_model>

  <action>
    1. Create `backend/app/core/security.py`:
       - Initialize `argon2.PasswordHasher()`.
       - Define `hash_password(password: str) -> str`.
       - Define `verify_password(plain_password: str, hashed_password: str) -> bool`.
       - Define `validate_password_strength(password: str) -> None`: enforces minimum 10 characters and checks against a list of common passwords (e.g. "password", "1234567890", "qwerty1234", "admin12345").
       - Define `create_access_token(user_id: UUID, role: str, demo_session_id: Optional[UUID] = None, expires_delta: Optional[timedelta] = None) -> str`: creates HS256 JWT using `settings.JWT_SECRET`, with `sub`, `role`, `demo_session_id`, `iat`, and `exp` (default 12 hours).
       - Define `decode_access_token(token: str) -> dict`: verifies signature and returns payload, raising JWTError on invalid/expired tokens.
    2. Create `backend/app/schemas/auth.py`:
       - `UserRegisterRequest`: `email` (EmailStr), `password` (str), `full_name` (str), `phone` (Optional[str]), `role` (str, default "citizen"). Validate `role in ("citizen", "responder")`.
       - `UserLoginRequest`: `email` (EmailStr), `password` (str).
       - `UserResponse`: `id` (UUID), `email` (str), `full_name` (str), `phone` (Optional[str]), `role` (str), `is_active` (bool), `demo_session_id` (Optional[UUID]), `created_at` (datetime).
       - `AuthResponse`: `user` (UserResponse), `token` (str).
  </action>
  <acceptance_criteria>
    - `security.py` hashes and verifies passwords using Argon2id.
    - `validate_password_strength` raises `ValueError` for passwords < 10 characters or common passwords.
    - `create_access_token` generates valid HS256 tokens decoded by `decode_access_token`.
    - `UserRegisterRequest` rejects roles other than "citizen" and "responder".
  </acceptance_criteria>
</task>

<task type="auto">
  <name>Task 2: Build auth dependencies and API endpoints</name>
  <files>backend/app/api/deps.py, backend/app/api/v1/auth.py, backend/app/api/v1/__init__.py, backend/app/main.py</files>
  <read_first>backend/app/core/security.py, backend/app/models/user.py, backend/app/models/responder.py, docs/LIFELINK_MASTER_SPEC.md §8.1</read_first>
  <action>
    1. Create `backend/app/api/deps.py`:
       - `get_current_user(request: Request, db: Session = Depends(get_db)) -> User`:
         - Extracts token from `request.cookies.get("ll_session")`.
         - If missing, checks `request.headers.get("Authorization")` starting with `"Bearer "`.
         - If no token, raises `HTTPException(401, detail={"error": {"code": "UNAUTHENTICATED", "message": "Authentication required"}})`
         - Decodes token via `decode_access_token`.
         - Queries `User` from DB by `id = payload["sub"]`.
         - If not found or `user.is_active is False`, raises 401 `UNAUTHENTICATED`.
         - Returns `user`.
    2. Create `backend/app/api/v1/auth.py`:
       - `POST /auth/register`:
         - Validates request body, checks if email already registered (returns 409 `CONFLICT`).
         - Hashes password.
         - Creates `User` row. If `role == "responder"`, creates `ResponderProfile` with default `readiness="off_duty"`.
         - Generates JWT token and sets `ll_session` cookie on response (`HttpOnly=True`, `Path=/`, `Max-Age=43200`, `Secure=settings.APP_ENV=="production"`, `SameSite="Strict" if settings.APP_ENV=="production" else "Lax"`).
         - Returns 201 `AuthResponse`.
       - `POST /auth/login`:
         - Finds user by email; validates password using constant-time check.
         - If user not found or password invalid, raises 401 `UNAUTHENTICATED` ("Invalid email or password").
         - If `user.is_active is False`, raises 401 `UNAUTHENTICATED` ("Account is suspended or deactivated").
         - Sets `ll_session` cookie on response and returns 200 `AuthResponse`.
       - `POST /auth/logout`:
         - Clears `ll_session` cookie (`Max-Age=0`).
         - Returns 204 No Content.
       - `GET /auth/me`:
         - Returns current user details and associated responder profile if applicable.
    3. Mount auth router in `backend/app/api/v1/__init__.py` and ensure `app/main.py` serves `/api/v1/auth`.
  </action>
  <acceptance_criteria>
    - `/auth/register` creates user and sets cookie.
    - `/auth/login` sets cookie on valid login and returns 401 on bad password.
    - `/auth/logout` deletes cookie.
    - `/auth/me` returns authenticated user using either cookie or Bearer token.
  </acceptance_criteria>
</task>
