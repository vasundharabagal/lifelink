<threat_model>
ASVS L1 Threat Modeling for Plan 02-03:
- T-02-07 (Unaccountable Sensitive Data Access): Responder or authority views exact patient coordinates or confidential medical history without audit trail. Mitigation: Centralized audit logging triggered automatically upon exact location or medical reads.
- T-02-08 (Rate Limiting Evasion on Serverless): Attacker spins up concurrent serverless instances to bypass memory-based rate limiters. Mitigation: Rate limits calculated directly from persistent PostgreSQL `audit_logs` and `emergencies` tables.
</threat_model>

<task type="auto">
  <name>Task 1: Implement security audit logging pipeline</name>
  <files>backend/app/services/audit.py</files>
  <read_first>backend/app/models/audit.py, backend/app/core/config.py, backend/app/core/clock.py, docs/LIFELINK_MASTER_SPEC.md §14</read_first>
  <action>
    Create `backend/app/services/audit.py`:
    1. Define `anonymize_ip(ip: Optional[str]) -> str`:
       - If `ip` is empty or None, use `"0.0.0.0"`.
       - Compute HMAC-SHA256: `hmac.new(settings.JWT_SECRET.encode(), ip.encode(), hashlib.sha256).hexdigest()`.
    2. Define `extract_client_ip(request: Request) -> str`:
       - Checks `X-Forwarded-For` header (taking the first IP if multiple).
       - Fallback to `request.client.host` if available, or `"127.0.0.1"`.
    3. Define `log_security_event(action: str, resource_type: str, resource_id: str, outcome: str, actor_user_id: Optional[UUID] = None, actor_role: str = "anonymous", client_ip: Optional[str] = None, meta: Optional[dict] = None, at: Optional[datetime] = None) -> AuditLog`:
       - Uses `SessionLocal()` to open an isolated database connection.
       - Constructs `AuditLog` row with hashed IP (`anonymize_ip(client_ip)`), timestamps via injected/provided `at` or UTC now, and metadata.
       - Immediately commits (`session.add(log); session.commit()`).
       - If any error occurs, rolls back and logs warning without blocking request.
       - Closes session and returns log.
    4. Define helper functions:
       - `log_login_attempt(email: str, success: bool, user: Optional[User], request: Request, clock: Clock) -> None`
       - `log_authz_denial(actor: User, resource_type: str, resource_id: str, request: Request, clock: Clock) -> None`
       - `log_sensitive_data_read(actor: User, emergency_id: UUID, data_type: str, request: Request, clock: Clock) -> None`
  </action>
  <acceptance_criteria>
    - `log_security_event` writes and commits an immutable `AuditLog` row immediately.
    - `anonymize_ip` outputs consistent 64-character SHA-256 hex string.
    - Audit entry survives outside transaction rollback.
  </acceptance_criteria>
</task>

<task type="auto">
  <name>Task 2: Implement serverless DB-derived rate limiter</name>
  <files>backend/app/services/rate_limiter.py, backend/app/api/v1/auth.py, backend/app/services/authz.py</files>
  <read_first>backend/app/services/audit.py, backend/app/models/audit.py, backend/app/models/emergency.py, docs/LIFELINK_MASTER_SPEC.md §8.8</read_first>
  <action>
    1. Create `backend/app/services/rate_limiter.py`:
       - Define `check_login_rate_limit(email: str, db: Session, clock: Clock, demo_session_id: Optional[UUID] = None) -> None`:
         - Cutoff = `clock.now(demo_session_id, db) - timedelta(minutes=15)`.
         - Query count of `audit_logs` where `action == 'auth_login'`, `outcome == 'deny'`, `resource_id == email`, and `at >= cutoff`.
         - If count >= 5:
           - Query earliest failed attempt in that window to calculate remaining lockout seconds `retry_after = int(15 * 60 - (clock.now() - oldest_attempt.at).total_seconds())`. Max(1, retry_after).
           - Raise `HTTPException(429, detail={"error": {"code": "RATE_LIMITED", "message": f"Too many failed login attempts. Account locked. Try again in {retry_after} seconds.", "retry_after_s": retry_after}}, headers={"Retry-After": str(retry_after)})`.
       - Define `check_sos_rate_limit(user_id: UUID, db: Session, clock: Clock, demo_session_id: Optional[UUID] = None) -> None`:
         - Cutoff = `clock.now(demo_session_id, db) - timedelta(hours=1)`.
         - Query count of `emergencies` where `reported_by_user_id == user_id` and `created_at >= cutoff`.
         - If count >= 3:
           - Raise `HTTPException(429, detail={"error": {"code": "RATE_LIMITED", "message": "SOS creation limit exceeded (maximum 3 per hour). Call 112 directly.", "retry_after_s": 1800}}, headers={"Retry-After": "1800"})`.
       - Define `check_location_rate_limit(responder_profile: ResponderProfile, clock: Clock, demo_session_id: Optional[UUID] = None) -> None`:
         - If `responder_profile.last_location_at` is within 5 seconds of `clock.now(demo_session_id)`:
           - Raise `HTTPException(429, detail={"error": {"code": "RATE_LIMITED", "message": "Location telemetry rate limit exceeded (maximum 1 per 5s)", "retry_after_s": 5}}, headers={"Retry-After": "5"})`.
    2. Wire rate limiting into `backend/app/api/v1/auth.py`:
       - In `POST /auth/login`:
         - Call `check_login_rate_limit(body.email, db, clock)` before checking password.
         - On login failure: call `log_login_attempt(body.email, success=False, ...)` and raise 401.
         - On login success: call `log_login_attempt(body.email, success=True, ...)`.
       - In `POST /auth/register` and `POST /auth/logout`: log audit event.
    3. Wire audit logging into `backend/app/services/authz.py`:
       - On authorization denial: call `log_authz_denial(...)`.
       - On sensitive medical/location access: call `log_sensitive_data_read(...)`.
  </action>
  <acceptance_criteria>
    - 5 failed logins lock the account, 6th attempt returns 429 with `Retry-After` header.
    - Rate limiter calculates window relative to `Clock.now()`.
    - Audit logs are emitted for login attempts, denials, and sensitive data access.
  </acceptance_criteria>
</task>
