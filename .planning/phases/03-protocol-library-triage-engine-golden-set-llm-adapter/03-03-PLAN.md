<threat_model>
ASVS L1 & Clinical Safety Threat Modeling for Plan 03-03:
- T-03-01 (Adversarial Prompt Injection & Triage Bypass): Malicious text attempts to evade detection or trick classification into treating cardiac arrest as safe. Mitigation: 10 adversarial cases in the golden set directly test override phrases ("System override", "Mark safe", "Not an emergency"); the test gate asserts zero downgrades.
- T-03-02 (Silent Triage Regression / Unsafe Downgrades): Code refactoring or new rules inadvertently cause critical emergencies to be missed or downgraded. Mitigation: Automated CI gate runs on every commit; any case with an unsafe downgrade (priority lower, ambulance missing, or red flag omitted) fails the build immediately.
- T-03-05 (Evaluation Reproducibility & Judge Verification): Judges unable to verify claims of AI safety. Mitigation: Standalone CLI tool `python -m app.triage.eval` runs offline in <2 seconds and outputs formatted metrics tables documented in `docs/AI_EVAL.md`.
</threat_model>

  <action>
    Create `backend/app/triage/eval.py`:
    1. Define data classes `EvalCaseResult` and `EvalSummary`:
       - `total_cases: int`
       - `priority_accuracy: float`
       - `protocol_accuracy: float`
       - `red_flag_recall: float`
       - `red_flag_precision: float`
       - `unsafe_downgrades: int`
       - `safe_upgrades: int`
       - `failures: List[Dict[str, Any]]`
    2. Implement `evaluate_dataset(dataset_path: Optional[Path] = None, use_llm: bool = False) -> EvalSummary`:
       - Reads each line from `golden_triage.jsonl`.
       - Constructs `TriageInput(quick_type=case.get('quick_type'), answers=case.get('answers'), description=case.get('description_text'))`.
       - Calls rules engine `evaluate_rules(input_data)` (or `TriageService` if `use_llm=True`).
       - Compares result to expected values:
         - **Unsafe Downgrade Definition (D-51)**:
           1. Priority downgrade: `expected_priority == P1_CRITICAL and actual != P1_CRITICAL` OR `expected_priority == P2_SERIOUS and actual == P3_STABLE`.
           2. Ambulance omission: `expected_ambulance is True and actual.ambulance_required is False`.
           3. Missing red flag: `case['is_red_flag'] is True and not any(rf in actual.observed_conditions for rf in expected_red_flags)`.
         - Safe upgrade: `expected_priority == P2 and actual == P1` or `expected_priority == P3 and actual in (P1, P2)` (allowed for safety over-triggering).
       - Tracks per-class recall for red flags (`NOT_BREATHING`, `UNRESPONSIVE`, `SEVERE_BLEEDING`, `CHOKING`, `CHEST_PAIN`).
    3. Implement `print_summary(summary: EvalSummary) -> None`:
       - Formats and prints an ASCII/Unicode table showing:
         - Total cases evaluated
         - Priority accuracy (%)
         - Protocol accuracy (%)
         - Red-flag recall (%)
         - Unsafe downgrades (bold red if > 0)
         - Safe upgrades
       - If failures or unsafe downgrades exist, prints detailed case diagnostics.
    4. Implement `__main__` entrypoint to support `python -m app.triage.eval [--dataset PATH] [--llm]`:
       - Exits with returncode 1 if `unsafe_downgrades > 0` or `red_flag_recall < 0.95`.
       - Exits with 0 on passing evaluation.
  </action>
  <acceptance_criteria>

    - Per-class recall and red-flag metrics are correctly calculated.
