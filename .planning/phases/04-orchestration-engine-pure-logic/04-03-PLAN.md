<threat_model>
ASVS L1 & Privacy/Oversight Threat Modeling for Plan 04-03:
- T-04-08 (Responder PII Exposure to Citizen): Citizen UI displays full name, phone number, or credential numbers of candidate responders. Mitigation: `citizen_summary` is strictly generated without personal names or IDs (e.g. "Nearby certified responder contacted (~3 min ETA)"); detailed `MatchExplanation` with names is restricted to authority and demo views.
- T-04-09 (Database Exhaustion / Unbounded Spatial Scan): Querying all responders in the entire nation on every emergency creation exhausts DB CPU. Mitigation: SQL bounding-box prefilter (`WHERE last_lat BETWEEN ... AND last_lng BETWEEN ...`) restricts candidate fetch to a strict latitude/longitude bounding box using the candidate's service radius.
- T-04-10 (N+1 Query Performance Collapse): Iterating through candidates triggers separate SQL queries for user, skills, and credentials. Mitigation: `selectinload` / `joinedload` eager-loading for relationships in `service.py`.
</threat_model>

    1. Create `backend/app/orchestration/engine.py`:
       - `build_match_explanation(emergency: EmergencyContext, track: TrackKind, ranked: List[ScoredCandidate] | List[ScoredAmbulance], rejected: List[RejectionDetail], clock: Clock, rules_version: str = "1.0.0") -> MatchExplanation`:
         - Builds weights dictionary matching `core/config.py` constants.
         - Generates `citizen_summary` via `build_citizen_summary(ranked, track)`.
         - Returns `MatchExplanation` containing:
           - `emergency_id`, `track`, `computed_at=clock.now()`, `rules_version`, `weights`
           - `ranked`: list of ranked candidates (top `MAX_COMMUNITY_CANDIDATES` or `MAX_AMBULANCE_CANDIDATES`)
           - `rejected`: list of all rejected candidates
           - `citizen_summary`: privacy-safe string
       - `build_citizen_summary(ranked: List[Any], track: TrackKind) -> str`:
         - If community track:
           - If `ranked` is non-empty: Top candidate category label + estimated ETA (e.g. "Contacting nearby certified responder (~3 min ETA)"). Never includes volunteer name or exact coordinates!
           - If empty: "Searching for qualified community responders nearby..."
         - If professional track:
           - If `ranked` is non-empty: "Dispatching emergency ambulance (~5 min ETA)"
           - If empty: "Contacting professional emergency medical services..."
       - `filter_and_rank_responders(candidates: List[CandidateProfile], emergency: EmergencyContext, clock: Clock, config: Settings) -> Tuple[List[ScoredCandidate], List[RejectionDetail]]`:
         - Loops through candidates:
           - Checks `evaluate_responder_eligibility`. If rejected, adds to `rejected`.
           - If eligible, scores with `score_responder` and adds to `eligible_scored`.
         - Ranks `eligible_scored` using `rank_scored_responders`.
         - Truncates ranked list to `config.MAX_COMMUNITY_CANDIDATES` (default 5).
         - Returns `(ranked, rejected)`.
       - `filter_and_rank_ambulances(units: List[AmbulanceCandidate], emergency: EmergencyContext, clock: Clock, config: Settings) -> Tuple[List[ScoredAmbulance], List[RejectionDetail]]`:
         - Loops through units:
           - Checks `evaluate_ambulance_eligibility`. If rejected, adds to `rejected`.
           - If eligible, scores with `score_ambulance` and adds to `eligible_scored`.
         - Ranks `eligible_scored` using `rank_scored_ambulances`.
         - Truncates ranked list to `config.MAX_AMBULANCE_CANDIDATES` (default 3).
         - Returns `(ranked, rejected)`.
       - `orchestrate_matching(candidates: List[CandidateProfile], ambulance_units: List[AmbulanceCandidate], emergency: EmergencyContext, clock: Clock, config: Settings) -> OrchestrationResult`:
         - Runs community track ranking (if emergency priority is P1 or P2, or if explicitly requested).
         - Runs professional track ranking (if emergency priority is P1 or P2, or if ambulance requested).
         - Builds `community_explanation` and `professional_explanation`.
         - Returns `OrchestrationResult`.
    2. Create `backend/tests/test_orchestration_explanation.py`:
       - Verify `MatchExplanation` structure with full score breakdown and subscores.
       - Verify `reasons[]` and `caveats[]` lists on ranked candidates.
       - Verify `citizen_summary` does not leak candidate name, phone, or exact location.
       - Verify fallback `citizen_summary` when zero candidates are eligible.
       - Verify truncation to `MAX_COMMUNITY_CANDIDATES` (5) and `MAX_AMBULANCE_CANDIDATES` (3).

         - Loads `Emergency` record from DB by `emergency_id`.
         - Checks active and past offers from `dispatch_offers` for this incident:
           - Sets `excluded_responder_ids` from offers with `status in ('DECLINED', 'EXPIRED', 'CANCELLED')`.
           - Sets `active_responder_ids` from offers with `status in ('OFFERED', 'ACCEPTED', 'ARRIVED')`.
           - Sets `excluded_ambulance_ids` and `active_ambulance_ids` similarly.
         - Computes bounding-box deltas around `emergency.lat`, `emergency.lng` using `bounding_box_delta_deg(max_search_radius_m, emergency.lat)`.
         - Queries `responder_profiles`:
           - Prefilters: `last_lat.between(min_lat, max_lat)`, `last_lng.between(min_lng, max_lng)`.
           - Prefilters: `readiness == 'available'`.
           - If `emergency.demo_session_id` is set: filters `users.demo_session_id == emergency.demo_session_id`. If None: filters `users.demo_session_id.is_(None)`.
           - Eager-loads `user`, `user.skills`, `user.credentials` using `selectinload`.
         - Queries `ambulance_units`:
           - Filters by `demo_session_id`.
         - Hydrates `CandidateProfile` and `AmbulanceCandidate` Pydantic objects.
         - Hydrates `EmergencyContext` from emergency fields and `emergency.triage["required_skills"]`.
         - Invokes `orchestrate_matching(candidate_profiles, ambulance_candidates, emergency_context, clock, settings)`.
